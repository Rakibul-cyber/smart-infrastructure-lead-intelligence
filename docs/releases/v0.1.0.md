# Smart Infrastructure Lead Intelligence v0.1.0

## Overview

Version `0.1.0` is the first documented project milestone for Smart
Infrastructure Lead Intelligence. It packages the core lead-research workflow:
controlled public website crawling, static and optional dynamic scraping,
rule-based signal detection, transparent scoring, Excel export, dashboard
summaries, Docker packaging, and CI configuration.

The application/package version is `0.1.0`. If a portfolio milestone release
needs to be named `v1.0.0`, the package version should be updated consistently
in a separate explicit task before that tag is created.

## Highlights

### Data collection

- Static page fetching with Requests and Beautiful Soup.
- Playwright Chromium rendering for JavaScript-driven pages.
- Static, dynamic, and automatic scrape strategy.
- Controlled multi-page crawling with URL deduplication.

### Lead intelligence

- Rule-based business signal detection with evidence excerpts.
- Transparent 0-100 lead scoring.
- Low, Medium, and High priority classification.
- Single-organisation and batch CSV workflows.

### Reporting

- Excel workbook export with `All Leads`, `High Priority`, `Evidence`, and
  `Run Summary` sheets.
- Terminal management dashboard with lead counts, contact counts, score
  statistics, top leads, and common signal summaries.
- Fictional demo data for safe local demonstrations.

### Reliability

- Retry handling for retryable request failures.
- Exponential backoff.
- Request pacing between crawled page URLs.
- Batch partial-failure handling and failure reporting.

### Developer experience

- Central configuration through environment variables and optional `.env`
  files.
- Structured console logging and optional file logging.
- Deterministic automated tests using local fixtures and fictional data.
- Documentation for architecture, module responsibilities, screenshots, and
  release preparation.

### Delivery and automation

- Docker runtime and test image support.
- Docker Compose CLI service.
- Docker smoke-test script.
- GitHub Actions workflow for Python and Docker checks.
- Dependabot configuration for dependency update checks.

## Example workflow

```text
CSV or single organisation

```

## Responsible use

This project is intended for legitimate public-data B2B/B2G research and
portfolio demonstration. It does not bypass authentication, CAPTCHA, anti-bot
controls, blocked access, or consent systems. Users should respect website
terms, robots rules, rate limits, GDPR, and applicable laws, and should keep
human review in the loop before outreach.

## Known limitations

- Signal detection is rule-based.
- Website structures vary.
- Public contact data may be stale, incomplete, or ambiguous.
- Dynamic pages may need site-specific selectors or waits.
- Lead scoring does not prove purchasing intent.
- Human review is required before business decisions or outreach.
